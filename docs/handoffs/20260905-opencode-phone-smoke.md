# Локальный OpenCode: обновить Record Idea Hub и базово проверить Samsung

## Цель

Сам скачай подготовленный APK, безопасно обнови приложение на подключённом
телефоне и проверь реальную доставку одной короткой записи с погашенным экраном.
Нужен рабочий результат, без нового широкого аудита, косметики и марафона тестов.
Владелец разрешил установку совместимого обновления и эту контрольную запись.
Сервер уже должен быть внедрён отдельным Codex; здесь production не меняй.

Работай в локальной ОС с доступом к телефону, не на удалённом сервере без ADB.
Определи ОС и используй существующие gh/ADB/Android SDK. На Windows предпочитай
native adb.exe, если WSL не видит USB. Не трать время на установку полной Android
Studio: недостающие command-line tools бери только из официального Android SDK.

## 1. Сам получи входные данные

Репозиторий: https://github.com/onedayonemasterpiece/record-idea-hub
Android PR: https://github.com/onedayonemasterpiece/record-idea-hub/pull/5
Backend PR: https://github.com/onedayonemasterpiece/my-data-hub/pull/39

Прочитай применимые AGENTS.md, `docs/RELIABILITY_20260905.md`, актуальный
`docs/ADB_HANDOFF.md` и результат предыдущего Codex из main:
`docs/verification/20260905-server-rollout.json`.
Получи их через GitHub сам; не проси владельца пересказывать SHA или прикладывать архив.

До установки требуется `status=READY_FOR_PHONE` и отсутствие блокера backend.
Если файла нет, проверь комментарии #39/#5 на результат; один зелёный CI или 401
не подтверждают внедрение. Без подтверждения сервера выполни только безопасную
диагностику и сообщи `BLOCKED_BACKEND`, не запускай новую запись.

Из отчёта возьми точные run/artifact/source SHA, APK SHA256 и сертификат.
Скачай через `gh run download <run_id> -R onedayonemasterpiece/record-idea-hub
-n <artifact_name> -D <new-local-directory>`; проверь, что run успешен, его SHA
и artifact ID совпадают с отчётом. Затем проверь реальные байты APK по SHA256,
package/version и `apksigner verify --print-certs`. Не выбирай «latest» вслепую.

## 2. Устройство, очередь и подпись — до установки

Запусти `adb devices -l`. Ожидается Samsung S21 Ultra, но модель, Android и
серийный идентификатор получи фактически. Все команды адресуй через `adb -s`.
При нескольких устройствах выбери однозначно целевое; иначе уточни только выбор.
При `unauthorized` или отсутствии устройства попроси одно физическое действие:
подключить USB, разблокировать телефон и подтвердить RSA-разрешение ADB.
Не обходи блокировку экрана, RSA или системные разрешения.

Обновляемый package: `com.onedayonemasterpiece.recordideahub.v11`.
Старый `com.onedayonemasterpiece.recordideahub` не удаляй и не подменяй.
RC4-контрольная версия — `1.1.0-rc4`, versionCode 5; фактическую кандидатку
бери из серверного отчёта. Не понижай уже установленную более новую версию.

Убедись, что запись сейчас не идёт. Зафиксируй установленную версию, наличие
очереди и session_id незавершённых записей без их текста. При доступном run-as
сохрани приватную согласованную копию локальной БД и незавершённых аудиофайлов;
не копируй активную SQLite без WAL/согласования. Если run-as недоступен,
зафиксируй ограничение: совместимое обычное обновление допустимо, удаление — нет.
Не публикуй backup, device token, настройки с секретами или личное аудио.
Копия encrypted preferences не заменяет сохранение Android Keystore.

Получи путь установленного base.apk через `adb shell pm path`, скачай его и
сравни сертификат с кандидатом, используя apksigner. Одинаковое имя package
или слово DEBUG не доказывают совместимость подписи.

При совпадении подписи и подходящем versionCode выполни
`adb -s <serial> install -r <apk>`: без удаления данных, `-d` и смены package.
Если ровно эта сборка уже установлена — повторная установка не нужна.

При несовпадении проверь только известный локальный Android debug.keystore и
документированное хранилище подписи проекта. Если найден доступный ключ с
сертификатом установленного приложения, им можно подписать копию проверенного
APK штатным apksigner. Не меняй dex/resources/package/version; проверь подпись
и фиксируй отдельно SHA256 исходного и реально установленного APK.
Приватный ключ не загружай в GitHub и не показывай в отчёте.
Если совпадающего ключа нет — `BLOCKED_SIGNATURE`, два публичных fingerprint и
сохранённая очередь. Не ищи ключ по всему диску и не пытайся извлечь его из APK.
**Запрещены adb uninstall, pm clear, root, обход signature check и пересоздание
приложения для обхода подписи, даже если старое руководство это советовало.**

## 3. Базовая приёмка — одна контрольная запись

Открой обновлённое приложение. Убедись, что конфигурация backend и очередь
сохранились, нет crash/ANR, видна нужная версия. Существующие permissions не
сбрасывай; недостающие RECORD_AUDIO/POST_NOTIFICATIONS предоставь штатно.
Не заменяй сохранённый device token новым и не выводи его. Google/Supabase/GitHub
ключи на телефон не передавай.

Проверь, что старые ожидающие записи видны; не сбрасывай reconciliation и не
нажимай принудительную платную переработку. Проверка статуса не должна менять
идентичность сессии или создавать дубликат.

Сделай одну запись с тестовой речью 15–30 секунд и уникальным неперсональным
маркером, например: «Проверка Record Idea Hub RC4, контрольный маркер <число>.
После завершения экран будет выключен. Это тест доставки после обновления».
Используй уже доступное воспроизведение речи через динамик компьютера; отдельный
Kaggle/Qwen-процесс не нужен. Если этот аудиопуть недоступен, попроси владельца
произнести фразу один раз. Не подменяй речь тишиной, фальшивым transcript или
персональной записью. Тестовая запись может попасть в штатный IdeaHub inbox;
не дублируй и не удаляй опубликованный пакет вручную.

Нажми «Завершить и отправить», сразу погаси экран и не держи Activity на переднем
плане ради отправки. Проверь уведомление/задачу доставки и её продвижение.
При подключении по USB можно внутри той же попытки коротко проверить потерю и
возврат сети, только если это делается штатно без риска потери ADB; верни исходные
настройки в finally. Это дополнительная проверка, не причина откладывать результат.
Не отключай Samsung battery optimization глобально, чтобы искусственно получить PASS.

После обработки включи экран, проверь терминальное состояние и реальный результат:
`published_verified`, `github_verified=true`, `server_audio_purged=true`;
ссылку/commit IdeaHub прочитай через GitHub на указанном commit и текущем main.
Должна быть одна логическая публикация с контрольным маркером. Локальное тестовое
аудио исчезает только после подтверждений; старые незавершённые записи не теряются.
Используй доступную безопасную проекцию локальной БД/авторизованный статус и UI;
недоступную проверку отметь явно. UI «2/2» — не доказательство отсутствия иных
физических запросов провайдеру; число POST не выдумывай.

## 4. Когда заканчивать

Один успешный end-to-end прогон достаточен. Не создавай новые записи ради красивых
скриншотов. Штатный путь этой записи — две генерации через общий серверный limiter;
не обращайся к Gemini напрямую. При quota/ambiguity не обходи ограничения и не
создавай новую сессию для повтора. Наблюдение ограничь десятью минутами; затем
сообщи конкретное текущее состояние/блокер, сохрани аудио, не заявляй PASS.

Если воспроизводится блокирующий дефект Android, исправь только его в отдельной
ветке record-idea-hub, добавь адресный тест, сохрани код и проверь новую совместимо
подписанную сборку. Разрешён один повторный контрольный прогон после конкретного
исправления; не запускай бесконечный цикл. Для дефекта backend оставь диагностический
комментарий в #39, не редактируй сервер с этого компьютера. Иконки, нефатальные
MPEG4Writer warnings, длинные записи, Doze-матрица, force-stop и перезагрузки
не входят в обязательную приёмку.

Сохрани короткий обезличенный результат в комментарии #5 (и локальный отчёт,
если записи в GitHub нет): `PASS` или конкретный `BLOCKED_*`, версия/package,
исходный и установленный APK SHA256, источник artifact, сертификат, модель/Android,
сохранность очереди, session_id теста, подтверждение работы с выключенным экраном,
GitHub URL/commit и что не проверено. Полные логи, токены, личные тексты и backup
в GitHub не публикуй. После PASS остановись, не придумывай следующий аудит.
