# Локальный OpenCode: готовый CI APK → обновление → один screen-off smoke

## Исправление владельца

APK уже собран и проверен в CI во время реализации ChatGPT. Серверный Codex
занимается ТОЛЬКО backend. Не жди от него APK, Android merge, новую main-сборку,
подпись или промежуточный JSON-файл. Сам скачай существующий артефакт ниже,
безопасно обнови приложение и базово проверь телефон. Не собирай неизменённый
код заново ради переноса из PR в main. Старые противоположные указания отменены.

Владелец разрешил совместимое обновление и одну короткую контрольную запись.
Работай в локальной ОС с доступом к Samsung через ADB, не на удалённом сервере.
Используй существующие gh/ADB/SDK; на Windows — native adb.exe, если WSL не видит USB.
Недостающие command-line tools бери из официального Android SDK, не устанавливай
полную Android Studio ради этой задачи. Production здесь не меняй.

## 2. Подтверждение сервера — отдельно от APK

Прочитай актуальные комментарии backend PR:
https://github.com/onedayonemasterpiece/my-data-hub/pull/39

Требуется фактический серверный результат `BACKEND_READY`: deployed SHA/image,
публичный authenticated v2 smoke, worker и сохранность очереди. Прежний
`READY_FOR_PHONE` допустим только при наличии этих фактов. Ни зелёный CI, ни один
401, ни заголовок статуса без доказательств не подтверждают внедрение.
Обязательный `docs/verification/20260905-server-rollout.json` больше не требуется;
достаточно комментария #39 со сведениями или ссылкой на существующий отчёт.

Прочитай применимые AGENTS.md и относящиеся к RC4 документы из ветки #5 либо
из main, когда он содержит нужную редакцию. До подтверждения backend можно
скачать APK и проверить подпись/устройство; не устанавливай и не запускай живую
запись против неподтверждённого backend. Сообщи конкретный BLOCKED_BACKEND.

## 3. Безопасное обновление

Выполни `adb devices -l`, фактически определи целевой Samsung, Android и serial;
все команды адресуй через `adb -s`. При нескольких неразличимых устройствах
уточни только выбор; при unauthorized попроси разблокировать телефон и подтвердить
RSA-разрешение. Не обходи блокировку экрана или системные разрешения.

Убедись, что запись не идёт. Зафиксируй текущую версию, session_id и наличие
незавершённой очереди без личного текста. При доступном run-as сохрани приватную
согласованную копию БД и незавершённого аудио, не копируя активную SQLite без WAL
или согласования. Недоступный run-as укажи как ограничение: совместимое обычное
обновление допустимо, удаление — нет. Backup и секреты не публикуй.

Через `adb shell pm path` получи установленный base.apk, скачай и сравни сертификат
с кандидатом. При совместимой подписи и отсутствии downgrade установи через
`adb -s <serial> install -r <apk>`. Уже установленную точную сборку не переустанавливай.
Не меняй package и не применяй `-d`. Старый package без `.v11` не трогай.

При несовпадении подписи проверь только известный локальный Android debug.keystore
и документированное хранилище подписи проекта. Доступным ключом, сертификат которого
совпадает с установленным приложением, можно переподписать копию проверенного APK
штатным apksigner без изменения dex/resources/package/version. Сохрани оба SHA256:
исходных CI-байтов и реально установленного APK. Ключ в GitHub не загружай.
Если совпадающего ключа нет — BLOCKED_SIGNATURE с двумя публичными fingerprint
и сохранённой очередью. Не ищи ключ по всему диску, не извлекай его из APK,
не переноси эту задачу на серверный Codex.

Запрещены `adb uninstall`, `pm clear`, root и обход проверки подписи. Копия
encrypted preferences не заменяет Android Keystore. Сохрани backend configuration
и device token; не перевыпускай token ради обновления. Секреты и личное аудио
не выводи в инструменты/отчёты. Недостающие разрешения предоставь штатно.

## 4. Одна короткая проверка

Проверь запуск без crash/ANR и сохранность очереди. Не сбрасывай reconciliation,
не создавай новые session_id вместо старых, не запускай принудительную платную
переработку. Сделай одну запись с тестовой речью 15–30 секунд и уникальным
неперсональным маркером. Используй доступную речь через динамик компьютера;
Kaggle/Qwen-процесс не нужен. Если аудиопуть недоступен, попроси владельца
произнести фразу один раз. Тишина или выдуманный transcript не заменяют тест.

Нажми «Завершить и отправить», сразу погаси экран; не удерживай Activity
на переднем плане. По уведомлению/задаче/доступной диагностике проверь продвижение
при выключенном экране. Не отключай глобально battery optimization для получения PASS.
Потеря/возврат сети в той же попытке — только дополнительная лёгкая проверка
без риска потери ADB; все временные настройки восстанови.

Проверь терминальные подтверждения `published_verified`, `github_verified=true`,
`server_audio_purged=true`, реальную публикацию с маркером через GitHub на указанном
commit и текущем main. Одна логическая запись, без дубля. Тестовое локальное аудио
удаляется только после подтверждений; старые незавершённые записи не теряются.
Не называй UI «2/2» доказательством количества физических provider POST.

Один успешный end-to-end прогон достаточен. Не повторяй ради скриншотов, косметики,
Doze-матрицы, длинных записей и перезагрузок. При quota/ambiguity не обходи защиту.
Наблюдение ограничь десятью минутами, затем сообщи фактический блокер без выдуманного
PASS. При воспроизводимом Android-блокере допустим адресный fix в GitHub, тест
и новая CI-сборка именно изменённого кода, затем один повтор smoke. Не поручай
сборку серверному Codex. Backend-дефект опиши в #39, production не редактируй.

Сохрани короткий обезличенный комментарий #5: PASS или BLOCKED_*, APK/source
identity, сертификат, модель/Android, сохранность очереди, session_id теста,
факты работы с выключенным экраном, GitHub URL/commit и что не проверено.
Полные логи, token, личные тексты и backup не публикуй. После PASS остановись.
