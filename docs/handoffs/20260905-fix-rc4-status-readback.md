## Исправление

1. Прочитай актуальные SyncEngine.kt, ApiClient.kt, SessionStore.kt,
   ServerReceiptReconciler.kt, TransferExecution.kt и нужный серверный status/create
   контракт. Проследи путь accepted complete -> следующий sync -> HTTP response ->
   parse -> сохранение подтверждений -> local purge. Не расширяй аудит на весь сайт.
2. Добавь безопасную диагностику именно этой границы: стадия, тип исключения,
   известный HTTP status/error code и ограниченные кадры стека своего кода.
   Не логируй body, Authorization, device token, настройки, аудио, тексты или
   несанацированное exception.message/cause. Сохрани полезную диагностику после
   перезапуска, не добавляя отдельную систему наблюдаемости. Ошибка чтения результата
   после complete не должна представляться пользователю как повторная отправка аудио.
3. Воспроизведи отказ тестом через реальный SyncEngine/API parser/SessionStore,
   подменяя сеть, а не весь результат движка. Проверь корректный published_verified
   ответ, промежуточную обработку, HTTP/JSON/локальную ошибку и возобновление после
   повторного открытия БД. Сначала установи конкретную причину и затем исправь её.
   Успешная проверка вспомогательной функции сама по себе не доказывает ремонт.
   Если без телефонного исключения причина не воспроизводится, назови это прямо:
   диагностическая правка не равна исправлению корня. Для телефона нужен только
   один адресный съём причины по существующей сессии, без новой записи/генерации.
4. После принятого complete только чтение статуса/необходимая идемпотентная
   транспортная сверка. Не повторять платную генерацию, не сбрасывать reconciliation,
   не подменять session_id, не чистить очередь и не заставлять пользователя
   перезаписывать уже опубликованное аудио. Локальный purge — только при трёх
   подтверждениях, как в действующем контракте.
5. Сохрани код и тесты в существующем PR #5 (если уже слит — отдельный короткий PR
   от текущего main). Прогони адресные тесты и обязательный Android CI. Новый APK
   делает CI после изменения кода, не серверный Codex. Зафиксируй точные run/artifact,
   source SHA, APK SHA256 и certificate SHA256. Никакой ручной подмены готовности.

## Подпись: не повторить предыдущую потерю времени

Сейчас на телефоне стоит именно CI RC4 из run 33953071610, artifact 9965493810:
APK SHA256 `1296361f1634c81f3d367561e0ac45c63d8321ede4ffa751a95446fab4a4ed84`;
сертификат `d76232a3b9b298bb31f244dcd47a8f8d8cf2f8c02501cd8a46f2f6aea0694a95`.
Постоянный ключ и возможность следующего in-place update в новом отчёте НЕ
подтверждены. Не объявляй новую CI debug-сборку совместимой только по package.
Проверь уже существующее решение подписи, не создавай новый случайный ключ и
не ищи старый RC2 keystore по дискам. Не публикуй приватный ключ в Git/артефактах.
Отсутствие ключа — отдельный конкретный блокер установки, а не причина
останавливать воспроизведение и исправление исходников. Новая переустановка или
потеря данных без отдельного разрешения запрещены: теперь есть незавершённая
локальная сессия с семью файлами. Старые 99/99 опубликованных записей описывали
состояние ДО уже выполненной переустановки, не нынешнюю очередь.

## Приёмка без перфекционизма

Сначала существующая сессия получает настоящий терминальный статус и локальную
очистку без новой генерации. Затем максимум один короткий реальный screen-off
прогон с разборчивой контрольной фразой. Физическую проверку делает локальный
OpenCode; известный adb.exe — `C:\platform-tools\adb.exe`, команды с явно
выбранным устройством. Не путать UID с PID при logcat и не обращаться через shell
к неэкспортированному RecordingService: использовать UI/уведомление приложения.
Системное состояние экрана Dozing не приравнивать автоматически к полной Doze-
приёмке. Не отключать глобально ограничения батареи ради зелёного результата.

Результат: конкретный дефект и регрессия, сохранённый commit, CI/APK и честная
граница «исходники исправлены / на телефоне подтверждено». Сервер, подпись,
микрофон и запись — разные проверки; успех одной не заменяет остальные.
После одного успешного прогона остановись. Не запускай новый широкий аудит.
