# Codex: внедрение Record Idea Hub RC4 и передача на телефон

## Задача и полномочия

Владелец поручил внедрение уже написанного пакета. Самостоятельно проверь,
слей готовые PR, обнови существующий сервер и подготовь точный APK для локального
OpenCode. Не ограничивайся планом и не переспрашивай разрешение на эти этапы.
Ограничения доступа и обязательные подтверждения инструментов сохраняются.
Телефон здесь не устанавливай: это отдельный следующий исполнитель.

Не начинай новый аудит продукта. Исправляй только реальные блокеры внедрения;
при исправлении кода добавь адресный регрессионный тест и сохрани изменения.

## Выполнение

   digest и фактические файлы запущенного backend. Сохрани параллельные рабочие
   изменения, включая Showcase/OAuth. Не заменяй более свежий runtime старым
   снимком из постановки. Если PR уже слит, проверь наличие изменений, не повторяй merge.

2. Перед переключением проверь свободное место и inode, доступность приватного
   spool. Зафиксируй предыдущий образ и конфигурацию для отката; сделай приватную
   согласованную копию SQLite через backup API и проверь её читаемость.
   Не копируй живой WAL как независимую резервную БД. Аудиокаталоги оставь на месте;
   не публикуй и не добавляй аудио/тексты/секреты в артефакты GitHub.
   Не останавливай активный запрос модели посередине ради деплоя: используй
   штатное завершение работы; при незавершающемся запросе зафиксируй блокер.

3. После зелёных обязательных проверок слей #39 штатно, без force/admin-обхода.
   Разверни проверенный immutable release через существующий deploy-процесс,
   сохранив spool, device token, общий Google AI limiter и действующие сервисы.

5. Проверь публичный ingress и фактическую политику запуска Nginx. Ранее проблема

## Передача следующему агенту — один файл

Сохрани фактический результат в `record-idea-hub/main`:
`docs/verification/20260905-server-rollout.json`.
Это небольшой отчёт, не новый framework или schema-проект. Достаточны поля:

- `status`: `READY_FOR_PHONE` только после успешного деплоя, smoke и получения APK;
  иначе `BLOCKED`, с конкретной причиной;
- `checked_at_utc`;
- `backend`: фактические `source_sha`, `image_digest`, `public_origin`, результаты
  authenticated/unauthenticated capabilities и приватная ссылка/путь отката без секретов;
- `android`: `repo`, `run_id`, `artifact_id`, `artifact_name`, `ci_source_sha`,
  `apk_filename`, `apk_sha256`, `certificate_sha256`, `package`, `version_code`;
- `phone_signing_compatibility`: `not_checked`, `live_phone_e2e`: `not_run`,
  `host_reboot_test`: `not_run`, `blockers`.

Не заполняй неизвестные значения предположениями. Прочитай сохранённый файл обратно
из GitHub; в комментариях #39 и #5 оставь ссылку на его точный commit. Коммит
отчёта после сборки не делает проверенный APK устаревшим: фиксируй его собственный
source SHA, не подменяй его новым documentation-only HEAD.

## Границы и завершение

Существующие нормальные задания может продолжать штатный worker через общий
limiter. Не сбрасывай `reconciliation_required`, не выдумывай complete manifest
из последнего сегмента, не меняй session_id и не повторяй неизвестный/непригодный
результат платной генерации. Старую блокированную сессию перечисли отдельно.

Дополнительных живых запросов Gemini для серверного smoke не создавай: одна
контрольная запись будет на телефоне. Не устраивай fault-injection в production.
Существующего CI и адресного smoke достаточно; новый код требует только
соразмерных проверок плюс обязательный CI. Ключ APK не генерируй заново ради
вида успешного обновления: совместимость с установленной подписью проверит OpenCode.

Заверши сообщением `READY_FOR_PHONE` либо `BLOCKED`, ссылкой на отчёт, deployed SHA,
точной сборкой APK и остаточными ограничениями. Не называй весь продукт принятым
до физической проверки телефона. Следующий шаг —
`docs/handoffs/20260905-opencode-phone-smoke.md` в record-idea-hub.
