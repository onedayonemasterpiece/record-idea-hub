# Codex: только серверное внедрение Record Idea Hub

## Исправление владельца — приоритет над прежней постановкой

APK уже собран и проверен в GitHub Actions. Codex НЕ занимается Android/APK:
не собирает, не скачивает, не переподписывает, не устанавливает, не запускает
Android CI, не сливает Android PR #5 и не готовит для него новый релиз.
Не устанавливай Android SDK на сервер. Прежнее поручение «подготовить APK»
и требование новой post-merge Android-сборки отменены, в том числе в старой
версии этого файла на commit e0128a1a9f8ec7e97ceec9966d11b4735b1037ad.

Твоя задача: внедрить уже написанные серверные исправления, проверить действующий
backend и сохранить результат в комментарии my-data-hub#39. Локальный OpenCode
сам скачает существующий CI APK и проверит телефон. Его работа не зависит от
выдачи APK серверным Codex или обязательного промежуточного JSON-файла.

## Завершение без дополнительной бюрократии

В комментарии #39 сохрани `BACKEND_READY` только после фактического успешного
внедрения и smoke, либо `BLOCKED` с конкретной причиной. Укажи время проверки,
deployed source SHA, image digest, origin, результаты authenticated/unauthenticated
capabilities, worker/очереди и остаточные ограничения. Если уже есть компактный
серверный отчёт, дай ссылку; создавать отдельный JSON только ради передачи не нужно.
Прочитай комментарий обратно. Эти сведения локальный OpenCode получит сам.

Не сбрасывай reconciliation_required, не выдумывай complete manifest из последнего
сегмента, не меняй session_id и не повторяй неизвестный результат платной генерации.
Обычные задания продолжает штатный worker. Дополнительных живых Gemini-запросов
и fault-injection для серверного smoke не создавай: контрольная запись будет
на телефоне. Новый широкий аудит и косметические правки не требуются.

`BACKEND_READY` подтверждает только сервер, не телефон и не проверку host reboot.
APK и установка полностью вне твоей задачи. Следующий исполнитель использует
`docs/handoffs/20260905-opencode-phone-smoke.md` в record-idea-hub.
